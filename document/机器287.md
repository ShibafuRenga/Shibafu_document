### Symbol以及编号

| Symbol | Id |

| S00 | 0 |
| W01 | 1 |
| W02 | 2 |
| W03 | 3 |
| W04 | 4 |
| W05 | 5 |
| W06 | 6 |
| W07 | 7 |

> 说明：本期玩法以收集 + lockFeature + nudge 为主。**S00 无独立玩法**；机台名中的 100x **无额外逻辑**（非独立倍率玩法）。

### 棋盘

- 展示 / 服务器：均为三轴，每轴 **5 行**（`5×3`）。
- 服务器直接下发可见 5 行，**客户端不再做 9→5 裁剪**。
- 每局结果需深拷贝记录各轴 **5 行** Symbol 与 Extra（非引用），供假 nudge / lockFeature nudge 对齐使用。

#### 牌面符号排布规则（服务器 5 行结果）

- **禁止连续两个 S00**。
- **wildStack**：连续的 W01～W07 一段；与 H/L 交界处用 S00 隔开（可见窗内可因条带上下超出而截断显示）。
- **其他 Symbol（H/L）**：与相邻异类符号之间用 S00 隔开；禁止 H/L 相连。
- **extra**：只出现在 **H01～H03、L01～L03** 上，且仅中间有效 3 行（可见 row 1..3）；不会出现在 S00 / Wild 上。

示例（5 行可见窗）：

- 无栈：`L01, S00, H03, S00, L02`
- 截断栈（峰偏上）：`W06, W04, W03, W02, W01`
- 下边缘压中奖线（可见 mid=row2 为 W01）：`W03, W02, W01, S00, H03`

### 中奖线

- **只有一条中奖线**，5 行坐标系下索引为：`2, 7, 12`（每轴中间行，`PAYLINE_ROW=2`）。
- 「Wild 在中奖线上」判定：上述位置的图标编号属于 **W01～W07**（不要求本局有线奖金额）。

### 收集

每轴一个收集栏，容量上限 **5**。

#### 收集数据

- 从每次 spin 的 `feature.CollectionState.collections` 读取（字典）。
- **收集数量** key：
  - `"collect_col0"` / `"collect_col1"` / `"collect_col2"` → 第 0/1/2 轴收集栏数量。
- **服务器下发的收集数 = 本局全部表现结束后的最终状态**（已包含本局收集增减与 lockFeature 内 nudge 消耗；客户端按上一终态 → 本局终态做差值动画，不以本地算术为准）。
- 有效位置 symbol 的 `extra` 决定本局飞火表现来源：
  - `extra == "1"`：当前轴收集栏 +1（飞向本轴）
  - `extra == "2"`：三轴各 +1（飞三份）；满 5 的轴 **跳过**，不给该轴飞

#### 条件 2 / wildStack 相关 collections key（同字典）

| key | 含义 |
|-----|------|
| `"reveal_col0"` / `"reveal_col1"` / `"reveal_col2"` | 假 nudge（条件 2）：`1`=该轴触发，`0`=不触发（**不再使用 `positions`**） |
| `"stack_col0_id"` / `"stack_col1_id"` / `"stack_col2_id"` | 该轴 wildStack 形状索引；`-1`=无 stack；`0..14`=下表索引 |

客户端用 `stack_col*_id` 查表得到完整 **9 格逻辑条带**（两端 W01、升到峰值再对称降回），再与当前 **5 行可见窗**对齐，用于 lock nudge / 假 nudge 卷入符号。

**wildStack 索引表（与文末详表一致）：**

| 索引 | 峰值 | 完整 9 格 |
|------|------|-----------|
| 0 | W05 | W01,W02,W03,W04,**W05**,W04,W03,W02,W01 |
| 1 | W06 | W01,W02,W03,W04,**W06**,W04,W03,W02,W01 |
| 2 | W07 | W01,W02,W03,W04,**W07**,W04,W03,W02,W01 |
| 3..14 | … | 见文末「wildStackID表」 |
#### 收集表现

- 某轴已满 5：该轴不再接收收集（含 `extra=="2"` 分到自己的那份）。
- 每个收集栏 5 个槽位；飞向「该轴从左往右第一个空槽」。多火同局需同步终点分配，避免写入同一槽。

**`extra=="2"` 特殊表现：**

- 飞行目标：未满轴各飞一份（最多三份）。
- 起飞前有一段等待 + **启动动画只播一份**（即使要飞三份，启动动画也只播一个）。

**两个预制体（不要混用）：**

| 预制体 | 用途 |
|--------|------|
| 起飞前 / 启动动画预制体 | 放在 **Symbol Overlay Lua 上挂载的某个 Transform / Image** 位置原地播启动动画（不是 Symbol 本体位置），只负责「起飞前等待」；**单独对象池维护** |
| 飞行预制体 | 启动结束后从池中取出（起点同为上述 Overlay 挂点），用 DOTween 飞向收集槽；**单独对象池维护** |

**收集流程：**

1. Overlay 上对应 Image `SetActive(false)` → 从池取 **启动动画预制体** 放到 Overlay 挂载的 Transform/Image 位置 → `await collectTakeOffWait`（播启动动画）→ 归还启动池。空方法：`PlayCollectTakeOffAnim`（`extra=="2"` 多目标时启动动画也只调一次）。
2. 仍从该 Overlay 挂点从飞行池取 **飞行预制体** → DOTween 飞向终点 → 到达后归还飞行池。空方法：`PlayCollectFlyAnim`（可选）。
3. 到达后收集栏对应槽位亮起，`await collectArriveWait` 后处理消失。空方法：`PlayCollectArriveAnim` / `PlayCollectSlotLight`。

两套预制体 **各用一个对象池**（初始大小均可配，建议默认 5）。

#### 收集相关可配置项（实现时全部做成可调常量 / Inspector / 配置表）

| 配置项 | 说明 |
|--------|------|
| `collectTakeOffPrefab` | 起飞前启动动画预制体 |
| `collectFlyPrefab` | 飞行用预制体 |
| `collectTakeOffWait` | 起飞前等待（= 启动动画时长） |
| `collectFlyDuration` | 飞行时长 |
| `collectArriveWait` | 到达后亮起停留再消失的等待 |
| `collectFlyEndPoints` | 各轴收集栏 5 槽终点 Transform / 坐标（或运行时解析） |
| `collectPerReelStagger` | 若需要：每轴起飞错开时间 |
| `takeOffFxPoolSize` | 启动动画预制体对象池初始大小，默认 5 |
| `flyFxPoolSize` | 飞行预制体对象池初始大小，默认 5 |

### nudge 与 lockFeature

#### nudge 实现（API）

- **使用 `Reel:RollStep(steps, duration, strip, animCurve)`**，不是 `reelStop`。
- 签名参考：`BlowFire.SlotLib.Reel:RollStep(steps, duration, strip, animCurve)`
- 工程参考（Lua）：
  - `GemstoneRushNudgeFeature.lua`（`reel.Reversed` + `RollStep`）
  - `ColossalDollarsDeluxeNudgeCommand.lua`
  - `DiamondStacksJackpotNudgeCommand.lua`
  - `ShamrockFortunePotView.lua` / `CloverFortuneTrioSpinGame.lua`
- 也可对照编辑器工程源码中的 `RollStep` 用法。
- nudge 曲线有多种：按「上一次结果牌面」该轴 **中间行** 的 Wild 编号区分；`RollStep` 封装旁留空方法 `PlayLockNudgeAnim(reelIndex, midWildId, steps, direction)`。

#### lockFeature 触发规则（两种，流程故意不同）

1. **条件 1（客户端判断）**：该轴中奖线位置为 W01～W07，且 **本局 spin 开始前** 该轴收集数 `>= 1` → 该轴即将进入 lockFeature。  
   - **计数时点**：`OnStartRolling` 瞬间快照，**不是** `onBounce` 时、也不是本局飞火落地后的 `collectionsBefore`。  
   - **反例**：轴 1 停轴时中奖线有 wildStack，但 spin 开始时轴 1 收集为 0；本局其他轴 `sub2` 飞火给轴 1 加了收集 → **不触发**条件 1。  
   - **不经过假 nudge**；进场当轴 **不算** lockFeature 内 nudge，**不消耗**收集。
2. **条件 2（服务器）**：`collections["reveal_col{reelIndex}"] == 1`（`reelIndex` = 0/1/2）→ 该轴即将进入 lockFeature。  
   - 走「特殊条件下的 Nudge 模拟」；该次假 nudge **不算** lockFeature 内 nudge，**不消耗**收集。
   - **不再使用** `CollectionState.positions`。

> **已确认**：同一轴同局 **不可能** 同时命中条件 1 与条件 2（互斥）。实现时两套流程可并列分支，无需优先级。同局若多轴 Cond2，按 Cond2 流程；Cond1+Cond2 同时有时只走 Cond2 流程（见 Controller）。

#### 特殊条件下的 Nudge 模拟（仅条件 2）

服务器给的最终意图牌面（**5 行**）中，该轴 wildStack 的最上边或最下边已压在中奖线（可见 row2）：

- **下边缘**在中奖线上：`preSetResult` 将 Symbol/Extra 整体 **上移 1 格**。
- **上边缘**在中奖线上：整体 **下移 1 格**。

表现时序：

1. `await` **可配置时间**（收集等待，见「等待策略」）。
2. `reveal_col{i}==1` 的轴 `RollStep` 假 nudge（数据上移→表现往下；数据下移→表现往上）；卷入符号按 `stack_col{i}_id` 对应的 9 格条带补全。空方法：`PlayFakeNudgeStart` / `PlayFakeNudgeEnd`。
3. 该轴进入 lockFeature（空方法：`PlayReelLockEnter`）→ 机台进入 lockFeature（空方法：`PlayMachineLockEnter`）。

#### 进 lock 前「等收集」的等待策略（重要）

进 lockFeature / 假 nudge **之前**对收集动效的等待，**一律用可配置的绝对时间 `await`，不要默认「等收集协程全部结束」。**

原因：产品上经常只要「看起来过了一半」或卡到某个节点，而不是全播完。实现约定：

| 配置项 | 用于 | 语义 |
|--------|------|------|
| `waitCollectBeforeMachineLock_Cond1`（原「时间 A」） | 条件 1：播线奖 / 进机台 lock 之前 | 有收集才 await；无收集 = 0。**可小于完整收集总时长**（例如只等一半） |
| `waitCollectBeforeFakeNudge_Cond2`（原「时间 B」） | 条件 2：假 nudge 之前 | 有收集才 await；无收集 = 0。是否等满由配置决定，默认按完整收集时长填，但代码仍走「配置时间」而非硬绑完成回调 |
| `lineWinPlayDuration` | 线奖动画等待 | 默认 2s；有线奖才 await，无线奖跳过 |

无收集时上述 wait = 0，直接进入下一步。

#### 收集消耗规则（已确认）

- **仅** lockFeature **已生效后**，该轴每次真正的 lock 态 nudge（SetResult 后的 `RollStep`）→ 该轴收集 **-1**。
- 条件 1 进场、条件 2 假 nudge：**都不算** lockFeature nudge，**不 -1**。
- UI 上的 -1 与 `collections` 终态对齐（服务器终态已含本次消耗）。

#### lock 局内仍可收集（已确认）

- lockFeature **进行中仍然可以收集**（未满轴出 `extra` 照常飞火）。
- 同局内二者 **时序错开、不冲突**：
  1. **先** lock 态 nudge + 消耗收集栏（SetResult 后 `RollStep`，对应 -1）；
  2. **后** 在轴 `onBounce` 时发生收集飞火（与普通局相同时机）。
- 服务器 `collections` 终态已包含「本局 nudge -1 + bounce 收集 +N」；客户端按终态做槽位表现，动画按上述先后播放即可。

#### lockFeature 状态

分为 **轴 lockFeature** 与 **机台 lockFeature**。

##### 轴的 lockFeature

1. **进入**  
   - 条件 1：该轴 `onBounce` 时进入 → 空方法 `PlayReelLockEnter(reelIndex, trigger=Cond1)`。  
   - 条件 2：假 nudge 结束时进入（也可用 onBounce，但必须判定是「本次假 nudge」）→ `PlayReelLockEnter(reelIndex, trigger=Cond2)`。
2. **退出**  
   - 该轴收集数为 0 时，轴停后退出 → `PlayReelLockExit(reelIndex)`。

##### 机台的 lockFeature

1. **进入**（条件 1 / 2 **顺序不同，按下列执行**）  
   - 本局存在任一轴进入轴 lockFeature → 机台也要进入 lockFeature。  
   - **条件 1**：  
     `await waitCollectBeforeMachineLock_Cond1`（无收集则 0）  
     → 若有线奖：播线奖并 `await lineWinPlayDuration`（默认 2s；无线奖跳过）  
     → 进入机台 lock → `PlayMachineLockEnter(trigger=Cond1)`。  
   - **条件 2**：  
     `await waitCollectBeforeFakeNudge_Cond2`（无收集则 0；时长可配成「整段」或「一半」等）  
     → 假 nudge → 轴 lock 进完  
     → 进入机台 lock → `PlayMachineLockEnter(trigger=Cond2)`  
     → 若有线奖再播并 `await lineWinPlayDuration`。
2. **退出**  
   - 所有轴都退出轴 lockFeature 后，轴一停下就退出机台 lock → `PlayMachineLockExit()`。

#### lockFeature 状态下的 spin

1. Spin 开始：已 lock 的轴 **lock（不转）**。空方法：`PlayLockSpinStart(lockedReels)`（可选，如锁屏特效）。  
2. `SetResult` 之后：**先**解锁并做 lock 态 nudge（`RollStep`）+ 消耗收集栏（-1）。空方法：`PlayLockNudgeStart` → `PlayLockNudgeAnim` → `PlayLockNudgeEnd` / `PlayCollectConsumed`。  
3. 未 lock、仍在转的轴：正常停轴；**收集飞火在轴 `onBounce` 时发生**（与普通局相同），lock 局内照常可收集。  
4. 同局顺序：**nudge/消耗在前，bounce 收集在后**，二者不冲突。

> 说明：处于 lock、本局只 nudge 不转的轴，若本局结果牌面有效位仍有 `extra`，收集是否在 nudge「停稳/等效 bounce」时触发，按与普通 `onBounce` 同一套收集入口处理（仍可收集）。

#### wildStack 总形状（服务器索引 + 客户端查表）

进入 lockFeature / 假 nudge 时，优先用本局 `stack_col{reel}_id`（**0..14**，见文末 wildStackID 表）查表得到完整 **9 格**对称条带并记录；`-1` 表示无 stack。

若索引缺失或未登记，可兜底：从当前 **5 行可见**连续 Wild 按规则还原（两端 W01、升到峰值再对称），但正常联机以服务器索引为准。

**判定规则（条带本身）：**

1. 完整条带长度 9，**两端为 W01**；
2. Wild **编号从小到大** 升到峰值（可跳号），再对称降回；
3. 整条回文对称。

可见 5 行是该 9 格条带在窗口上的截断；nudge 滑动窗口时用条带补卷入格。

#### 由前后牌面推断 nudge 格数

列 1 = 前一次 **5 行**可见，列 2 = 当次 **5 行**可见。结合已记录的 9 格总形状，对齐后比较 `viewOffset` 得方向与步数，再 `RollStep`。

# 数据整理

1. **收集**  
   - `CollectionState.collections`，收集数 key：`"collect_col0"|"collect_col1"|"collect_col2"`。  
   - **值为本局全部表现结束后的最终数量**。  
   - `extra=="1"` → 表现上本轴 +1；`extra=="2"` → 三轴各 +1（满 5 跳过）。  

2. **lockFeature**  
   - 条件 1：中奖线位为 W01～W07，且 **spin 开始前** 该轴收集 `>=1`（`collectionsAtSpinStart`；不含本局 bounce 新增）→ 客户端在 `onBounce` 判断。  
   - 条件 2：`reveal_col{0|1|2}==1` → 假 nudge 进 lock（**不用 `positions`**）。  
   - 服务器牌面 **5×3**；中奖线 `2,7,12`；`stack_col*_id` 查表得 9 格 wildStack。  
   - 条件 2 假 nudge：服务器给 **最终意图 5 行**；客户端 preSetResult 先错开再 RollStep 回正。

3. **消耗与收集（lock 局）**  
   - 仅 lockFeature **态内**每次 nudge 对应收集 -1（体现在服务器终态）。  
   - 条件 1 进场、条件 2 假 nudge：**不消耗**。  
   - lock 局内 **仍可收集**；同局顺序为 **先 nudge+消耗，后 onBounce 收集**。

# 带多次回弹动画曲线的nudge

这台机器的nudge可能有多次回弹，而Reel不支持一次nudge/spin曲线多次回弹。需要换一种思路，不能用rollStep。

## 实现（UI NudgeBehaviour，已落地）

- **不再使用** `Reel:RollStep`。
- 场景挂载：
  - `BlazingWild100xNudgeView`：全套 Symbol Sprite（`sprite_S00`… / 或 `symbolSprites[id]`）
  - 3 个 `BlazingWild100xNudgeBehaviour`（`reelIndex=0/1/2`）：各 9 个已对齐 `symbolImage_0..8` + `root`
- 流程：`MaskReel(S00+lock)` → 按 `startCol+shape` 刷 9 Image → `root` 按曲线百分比平移 → `RestoreReel(endCol)`
- 时长由调用传入；曲线只定形状（`Evaluate(progress * curveEndTime) / curveEndValue * deltaY`）
- 曲线**倒数第二个控制点**触发 `NudgeBehaviour:OnPenultimateCurvePoint()`（空实现，可覆写）
- lock / 假 nudge 共用：`Helper.PlayStackNudge`

# 整理一下anticipation播放规则

这台机器只有一线，线上的判断比较简单，但是anticipation规则又麻烦了(又带上奖励倍数了，并且这个奖励倍数是带锁轴的，顺序就会很麻烦)

1. 首先定义一下"前两轴":这台机器有“锁轴”的情况，所以“前两轴”会比较特殊，不是reel0和reel1。如果有两个锁轴，那么这两个锁着的轴就是”前两轴“。如果有一个锁轴，那么这个锁轴+从左往右未锁的第一个轴是“前两轴”。没有锁轴就是从左往右的前两个轴。明确前两轴后开始讲anticipate规则:
2. 明确一下wild对应的multiplier映射：
symbol | multiplier
W01 | 0X
W02 | 2X
W03 | 3x
W04 | 5X
W05 | 10X
W06 | 20X
W07 | 100X

1. 如果中奖线上前两轴均为wild走以下anticipate规则：
   当multiplier的和小于等于4时，动画集名为"anticipation1_" + (reelIndex + 1)
   当multiplier的和大于等于5时，动画集名为"anticipationlong1_" + (reelIndex + 1)
2. 如果中奖线上前两轴只有一个wild走以下anticipate规则：
   当该wild为W04以及以上时，我会给你一个key,value对，key为中奖线前两轴的非wild轴上的symbolId：

```
      H01:10

      L02:2
      L03:1
```
   将该value与wild对应的multiplier相乘，如果在[10,40)区间内，动画集名为"anticipation1_" + (reelIndex + 1)。如果在[40,+)区间内，动画集名为"anticipationlong1_"+(reelIndex + 1)
在除1和2的其他情况下不播anticipation。并且anticipation和anticipationlong用两种不同的anticipation曲线

## reel_seperator

这个是四个animator，reel_seperator1和reel_seperator2对应轴1，reel_seperator2和reel_seperator3对应轴2，reel_seperator3和reel_seperator4对应轴3。直接创建一个新的view来控制这四个动画状态机。下面开始讲这个view上各个动画的播放需求：

## 机台lockFeature状态

这个是两个canvasGroup来决定，lockFeatureGroup和baseGroup两个CanvasGroup，进入机台lockFeature状态渐变打开lockFeatureGroup，变完后关闭baseGroup，退出lockFeature状态时打开baseGroup，然后渐变关闭lockFeatureGroup。默认是baseGroup状态。这俩Group挂载在spinGame上。注意保存恢复的时候也需要机台lockFeature状态正确。

在nudgeView上挂载了nudge_arrow_lock0,nudge_arrow_lock1,nudge_arrow_lock2三个状态机对应三轴。在lockFeature状态中的nudge中，对应方向播nudge_arrow_up或者nudge_arrow_down，动画时长0.5s，需要按照wildStack的wild等级区分播放次数，给出配置表，现在0,1级播1遍，2，3级播3遍
